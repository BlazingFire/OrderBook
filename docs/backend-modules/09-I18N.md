# 09 — The translation layer: English only, through `t()`

Status: **built** (`shared/src/i18n/`). Part of the backend build plan in `docs/BACKEND_MODULES.md`;
this document specifies the string layer.

Scope: both panels, every string a person reads. The product is **English-only**. There is no second
language, no language picker, no per-machine or per-user language setting and no language
requirement of any kind. What stays is the *string system*: every sentence a screen, an error or an
audit row shows still lives in one catalogue, `shared/src/i18n/en.ts`, and is looked up through
`t()`. That keeps wording in one greppable place, keeps the server out of the business of writing
sentences, and keeps tokens stable for data that outlives any one version of the text.

---

## 1. The groundwork

### 1.1 Every permission catalogue entry carries a token

`shared/src/domain/permissions.ts` — the comment is the contract:

```ts
interface CapabilityDefinition {
  key: string;
  group: CapabilityGroup;
  /** Translation token; the renderer never hard-codes the English. */
  labelToken: string;
}
```

The served catalogue mints two more token families, `module.<module>` and `capabilityGroup.<group>`,
and `ROLE_TEMPLATES` carries a `nameToken`. A new capability reaches the screen with one catalogue
entry and no UI change. `shared/tests/i18n-coverage.test.ts` proves every one of those tokens
resolves (§10.2).

### 1.2 The audit trail stores tokens plus params, not sentences

`activity_log` has no column that holds prose. `(entity_type, action)` is a token pair and `details`
is a JSONB parameter bag. The text a person reads is produced when the row is shown, from
`en.ts`, so rewording a sentence changes no stored row — see §2.2.

### 1.3 The error envelope carries structured facts

`AppError` has `code` and `details`; the HTTP transport emits them
(`master/src/http/middleware/error-handler.ts`) and the browser client models them. The envelope
gained two optional fields, `messageKey` and `params`, and kept `message` (§7).

---

## 2. The central decision

> **The server never renders a user-facing sentence.** It returns a stable `messageKey` plus named
> params, and the client renders.

### 2.1 Why

One Master serves several Office Panels on a LAN. When the Master refuses a command it is answering
a socket, not a person, and the same refusal is also written to `activity_log`, which is read later
by somebody else on another machine. The place that paints the pixels is the browser, so that is
where text is produced. The server's job is to say *what happened* in a form that is permanent and
free of wording.

### 2.2 The hash chain needs no change

`activity_log` rows are chained by a trigger whose digest covers `prev_hash`, `sequence`,
`entity_type`, `entity_id`, `action`, `actor_type`, `actor_id` and `details`. Every one of those is a
permanent fact: an id, a token, a parameter bag. **None of them is a rendering.** The rendering
contract sits outside the chain: `activityMessageKey('lead', 'stage_changed')` is a function of two
values the digest already covers, evaluated in the browser, and rewording the catalogue changes no
byte that was ever hashed. The table refuses UPDATE and DELETE (`activity_log_immutable()`), so this
is the only arrangement that works.

### 2.3 The error envelope needs only additive fields

The HTTP envelope is `{ error, message, details? }` and the socket ack is
`{ ok: false, error, code?, missingPermission? }`. Both carry the two optional fields `messageKey`
and `params`. No existing field changes shape. `message` stays: it is the last-resort tier of the
client fallback (§5.2) and it is what the Master's own logs print.

### 2.4 It does not degrade offline

The catalogue is compiled into each panel's bundle before the panel has ever contacted a Master.
Rendering needs no network, no Master and no cache, and errors that were already surfaced stay
legible because they were never prose in the first place. The Office's own `503` code,
`unavailable`, renders from `error.unavailable` while disconnected. The catalogue is deliberately
**not** carried in `SyncSnapshot`: a bundle is the correct home for text that changes only when the
code changes.

---

## 3. The catalogue is compiled TypeScript, not a database table

**A key exists only because code references it.**

| Property | `en.ts` catalogue | `catalogue` table |
|---|---|---|
| Misspelt key | Compile error | Renders blank at runtime, in front of a customer |
| Key referenced but never defined | Compile error | Silent |
| Key defined but never referenced | Findable by grep | Accumulates forever |
| Reaches an offline panel | In the bundle | Needs a sync path, a permission, a conflict story |

A table would also need a migration, a permission key, a snapshot field and a merge policy, for a
dataset that changes only when someone edits code.

`en.ts` is the single source of truth: `EN_MESSAGES = {...} as const`, and `MessageKey` is
`keyof typeof EN_MESSAGES`. Adding a key means adding it in that one file.

---

## 4. `shared/src/i18n/` — the file specification

```
shared/src/i18n/
  en.ts          THE source of truth. `EN_MESSAGES = {...} as const`
  keys.ts        MessageKey, Placeholders<S>, ParamsFor<K>, CountKey, LocaleCatalogue
  locales.ts     the one `Locale` ('en') and its guard
  translate.ts   t(), tCount(), createTranslator() — NO number formatting
  activity.ts    activityMessageKey(), ACTIVITY_TOKENS, renderActivity()
  errors.ts      ErrorPayload, errorMessageKey(), TranslatableError, hasMessageKey()
  index.ts       barrel, explicit .js specifiers (NodeNext house convention)
```

No migration, no table, no permission key.

### 4.1 `en.ts` — one flat object, `as const`

```ts
export const EN_MESSAGES = {
  'permission.lead.convert': 'Convert a lead to an order',
  'module.leads': 'Leads',
  'error.forbidden.missingPermission': 'You do not have permission: {permission}',
  'error.lockedOut': 'Too many failed attempts. Try again in {seconds} seconds.',
  'activity.lead.stage_changed': '{actor} moved this lead to {to}',
  'common.save': 'Save',
  'count.leads.one': '{count} lead',
  'count.leads.other': '{count} leads',
} as const;
```

Rules, each of which a test enforces (§10):

- **Flat, dotted keys.** Not nested objects: a flat object makes `keyof typeof` a usable union and
  keeps the whole catalogue greppable.
- **`as const` is load-bearing.** Without it every value widens to `string` and `Placeholders<S>`
  has nothing to read.
- **Named placeholders, never positional, never concatenation.** `{permission}` survives a rewording
  of the sentence; `%s` and `'You do not have permission: ' + key` do not.
- **No pre-formatted numbers, no thousands separators, no currency symbol inside a message.** Numbers
  arrive as params and are formatted by the caller (§9).
- **Plural forms are two sibling keys**, `.one` and `.other`, never a number glued to a sentence
  (§4.4).

Namespaces:

| Namespace | Holds |
|---|---|
| `permission.*` | One per capability plus one per module×action key |
| `module.*`, `action.*`, `capabilityGroup.*`, `roleTemplate.*` | One per entry of the matching catalogue in `permissions.ts` |
| `error.*`, `validation.*` | One per `AppError` subclass and per stable code, plus finer per-throw-site tokens (§7) |
| `activity.*` | `activity.<entityType>.<action>` (§4.5) |
| `common.*`, `count.*` | The small shared set |
| screen copy | Everything else a screen shows, grouped by screen or feature |

A token whose key set is derivable from something the backend owns (a catalogue, an enum, a CHECK
constraint) is proved complete by a pure test over compiled TypeScript. A token that exists because a
designer wrote a sentence on a mockup is only as complete as the screen that uses it.

### 4.2 `keys.ts` — the type machinery

```ts
export type MessageKey = keyof typeof EN_MESSAGES;

/** The {named} placeholders inside a literal message template. */
export type Placeholders<S extends string> =
  S extends `${string}{${infer Name}}${infer Rest}` ? Name | Placeholders<Rest> : never;

export type ParamsFor<K extends MessageKey> =
  [Placeholders<(typeof EN_MESSAGES)[K]>] extends [never]
    ? []
    : [params: Record<Placeholders<(typeof EN_MESSAGES)[K]>, string | number>];
```

`ParamsFor` is a **tuple** type spread into the signature, so a message with no placeholders takes no
params, a message with placeholders requires exactly those, and a misspelt or invented placeholder is
a compile error. The tuple wrapper in `[Placeholders<…>] extends [never]` is deliberate: a bare
conditional distributes over the union and silently produces `never` for keyed messages.

`CountKey` is the set of stems that have both a `.one` and an `.other` sibling — the only valid
`tCount()` inputs.

### 4.3 `locales.ts` and `translate.ts`

`Locale` is the single value `'en'` and `DEFAULT_LOCALE` is `'en'`. A stored or wire value that is
anything else is ignored and English is used: nothing crashes, nothing is migrated. Where a
function still takes a `locale` argument it is typed `'en'`.

`t()` substitutes named placeholders with `String(value)` and nothing else — **it has no number
formatting capability**, so it cannot break the rule in §9. An unknown placeholder is left literally
in place, not blanked. A key missing from the catalogue at runtime returns the raw key: never blank,
never a throw.

### 4.4 `tCount()`

```ts
tCount('count.leads', n, { … })  →  n === 1 ? 'count.leads.one' : 'count.leads.other'
```

Selection uses `Intl.PluralRules` — ECMA-402 core, available in Node and in every browser this ships
to, with no network and no dependency. `count` is injected as the `{count}` param, so the sentence is
authored whole and a number is never concatenated onto it.

### 4.5 `activity.ts` — the contract the Logs screens render against

```ts
export const ACTIVITY_TOKENS: ReadonlySet<string>;          // frozen, APPEND-ONLY
export function activityMessageKey(entityType: string, action: string): MessageKey | null;
export function renderActivity(t: Translator, input: ActivityRenderInput): string;
```

`activityMessageKey` returns `null` rather than throwing, and `renderActivity` falls back to showing
the raw `entity_type` / `action` pair. That is not defensive coding for a case that cannot happen:
`action` is free-form `TEXT` with no `CHECK` constraint, so a row whose action post-dates this
bundle's catalogue *will* occur. Showing `lead · stage_changed` is a worse sentence than the
rendered one and a far better outcome than a blank cell in an audit trail.

**Append-only.** `activity_log` refuses UPDATE and DELETE by trigger, so retiring a token would orphan
rows that can never be corrected. The rule is enforced by `shared/tests/activity-tokens.lock.json`
(§10.2) — and honestly, by a person who could edit the lockfile. The comment above `ACTIVITY_TOKENS`
states the real justification, because a lockfile is a speed bump and the reasoning is the actual
guard.

### 4.6 `errors.ts` — one wire shape for both transports

```ts
export interface ErrorPayload {
  error: string;                       // stable code — branch on this, never on the message
  message: string;                     // English, derived from messageKey; the last-resort tier
  messageKey?: MessageKey;
  params?: MessageParams;
  details?: Record<string, unknown>;
}
export function hasMessageKey(value: unknown): value is { messageKey: MessageKey };
export function errorMessageKey(code: string): MessageKey;   // coarse `error.<code>` token
```

Declaring the payload once is what stops the HTTP envelope and the socket ack drifting apart.
`errorMessageKey` is **total over every stable code the two servers emit**, with `error.unknown` as
the last resort. A computed number never goes into a message string: `locked_out` is
`error.lockedOut` with `{ seconds }` — a token and a param, which is the whole pattern in one line.

## 5. The web side

Both web apps render through the same `t()`, imported from `@orderbook/shared`/`@orderbook/ui`.
There is **no provider that switches language, no picker, no persisted language setting**.

### 5.1 Raw text is never written in JSX

Every sentence, label, placeholder, title and `aria-label` is a key in `en.ts` (§8 is the lint gate).
Identifiers — record ids, device codes, chain hashes, permission keys — are verbatim and are the one
legitimate raw text (§9).

### 5.2 Errors render in three tiers, never blank

1. `messageKey` + `params` through `t()`;
2. else the coarse `error.<code>` token (`errorMessageKey(code)`);
3. else the envelope's own `message`.

---

## 6. Changed server and client files

The socket ack grew `messageKey` and `params` next to `code`, so a refusal that crosses the Master →
Office → browser path keeps its token end to end. `respond()` in `master/src/realtime/hub.ts`
forwards `code`, `messageKey` and `params` for every `AppError` subclass (it once dropped them for
`ConflictError`, which surfaced as a permanent 502). The Office's `forward()` turns a refused command
into a `403` with `error: 'forbidden'`, `details.permission` and a `messageKey`.

Permission labels are rendered from the served catalogue's `labelToken` through `t()`; the two local
"humanisers" that used to print raw keys were replaced by it.

---

## 7. Error tokens — `messageKey` on `AppError`

`AppError` takes a `messageKey` and `params` and derives its English `message` from them, so the
English fallback cannot drift from the token. Throw sites name a finer token where the sentence
matters (`error.conflict.nameTaken`, `error.conflict.staleVersion`) and otherwise fall back to the
coarse `error.<code>`.

**`message` stays byte-identical** to what a caller saw before the tokens existed: existing tests,
log lines and the `forward()` path read it. A change to a sentence is a change to `en.ts`, and the
test `master/tests/errors-i18n.test.ts` asserts `AppError.message` equals the rendered token for every
subclass.

---

## 8. The lint gate

`tools/eslint-rules/no-untranslated-jsx-text.js`, registered in `eslint.config.js` as an in-repo
flat-config plugin with no new dependency. It flags `JSXText` containing a letter, and string
literals passed to `placeholder`, `title`, `aria-label`, `alt` and `label`. It skips
`<Untranslated>`, punctuation-only and digit-only text, and `*.test.tsx`. Scope is
`{master,office}/web/src/**/*.tsx`: server files are full of legitimate literals (log messages, SQL,
column names) that no person ever reads.

`<Untranslated>` is a semantic wrapper for text that is deliberately not a message — an id, a code, a
fingerprint — rather than a disable comment, so the exemption documents itself at the point of use.

---

## 9. Numbers, ids and fingerprints are formatted, never reworded

| Category | Example | Rule |
|---|---|---|
| Counts and quantities | `12 boxes` | `{count}` param, digits unchanged |
| Record ids | `RL0000000004` | Verbatim, `<Untranslated>` |
| Device codes, pairing codes | — | Verbatim |
| Chain hashes | 64 hex chars | Verbatim, monospace |
| Permission keys | `field.saleRate.view` | Verbatim in a `<code>` — the *label* comes from the catalogue, the key does not |
| Product codes, party codes | — | Verbatim |
| Dates and times | — | Formatted with an explicit, pinned locale |

The software carries no money at all, so no message holds a currency figure.

Enforcement: `t()` has no formatting capability (§4.3); `en.ts` contains no pre-formatted number or
thousands separator (a test asserts it, §10.1); `format.ts` in each web package passes an explicit
locale rather than following the browser; and `<Untranslated>` documents the identifier category.

**Date safety.** `DATE` columns once came back a day early east of UTC because `toISOString()`
converts to UTC first; `toIsoDate` (`master/src/repositories/mappers.ts`) is the existing fix, and
nothing in the string layer constructs a `Date` from a `DATE`-derived value.

## 10. Tests and gates

`10-TESTING.md` is the sole test register. What follows is *what these suites must prove*. Every one
is **pure** — no `describe.skipIf`, no database — because a translation gate that can skip is not a
gate.

### 10.1 `shared/tests/i18n.test.ts` — the renderer

- `t()` substitutes named placeholders; an unknown placeholder stays literally in place.
- A record id, a device code and a 64-character chain hash pass through **byte-identical**.
- `tCount()` selects `one`/`other` correctly and never concatenates a number onto a sentence.
- A key absent at runtime returns the raw key — never blank, never a throw.
- **No string in `en.ts` contains a digit group separator or a pre-formatted number.**

### 10.2 `shared/tests/i18n-coverage.test.ts` — the contract

- Every key in `PERMISSIONS` has a `permission.<key>` token; every `MODULES`, `ACTIONS` and
  `CAPABILITY_GROUPS` entry has its `module.*`, `action.*` and `capabilityGroup.*` token; every
  `ROLE_TEMPLATES` `nameToken` exists.
- `ACTIVITY_TOKENS` is a superset of `shared/tests/activity-tokens.lock.json`, which is read with
  `readFileSync` and **never imported** (`tsc` does not copy JSON into `dist`).

### 10.3 The type-level tests

`tsconfig.test.json` includes `shared/tests/**/*.ts`, so type assertions live in ordinary test files.
Negative assertions use `@ts-expect-error`, which `tsc` verifies in both directions:

```ts
// @ts-expect-error — this key requires params
t('error.forbidden.missingPermission');
// @ts-expect-error — 'permision' is not a placeholder in this message
t('error.forbidden.missingPermission', { permision: 'x' });
```

### 10.4 `master/tests/i18n-tokens.test.ts` — the source-reading invariant

Written in the style of `master/tests/credential-invariants.test.ts`: it reads `master/src` and checks
that every literal `(entityType, action)` pair handed to the audit writer has an `activity.*` token
(§11), and that `details` covers the template's placeholders.

### 10.5 The end-to-end error path

- `AppError.message` equals the rendered token for every subclass (§7).
- `respond()` sets `code`, `messageKey` and `params` for a `ForbiddenError` **and** a `ConflictError`.
- An Office `forward()` of a refused command surfaces **403** with `error: 'forbidden'`,
  `details.permission` and a `messageKey`.
- `renderActivity()` falls back to the raw `entity_type`/`action` pair for an action no catalogue has
  seen.
- The lint rule flags a bare JSX literal, ignores punctuation-only and digit-only text, and is silent
  inside `<Untranslated>`.

## 11. The activity token catalogue

`activity_log.action` is free-form `TEXT` with no `CHECK` constraint, so `ACTIVITY_TOKENS` cannot be
derived from the schema. Somebody must own keeping it complete, and the owner is whoever adds an
audited action: **every new audited action needs an `activity.<entityType>.<action>` token in
`en.ts` and an entry in the lock file, and must not log chat messages, presence or print ticks.**

`master/tests/i18n-tokens.test.ts` reads the source for literal `entityType`/`action` pairs and fails
when one has no token. Two traps in writing it, both worth remembering: an `action` computed from a
variable cannot be matched by a source scan, so such sites must go through a typed constant list; and
a regex over `master/src` must not be fooled by an `action:` key inside an unrelated object literal.

---

## 12. Build order and what depends on this

`AppError`'s constructor signature is a dependency of the other modules, so this layer lands first:
the catalogue and `t()`, then the error tokens and the socket ack fields, then the activity tokens and
the Logs rendering, then the screens. Each later stage adds its keys to `en.ts` and nothing else.
