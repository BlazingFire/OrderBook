# OrderBook batch 1.3 — integrated implementation plan (final, review applied)

## 1. Context

The owner asked for one large batch:
- six realtime and sync rules: instant offline/sync state, Master-assigned pending-order numbers, live presence avatars, complete logs, a notice after 1 h offline, and deterministic offline ordering;
- two new modules, Chatroom and Printroom;
- a Server Master tier with a master key;
- Basic Home and a refreshed Master UI;
- reports and Excel/PDF exports on both panels;
- party CSV/XLSX import and export;
- backup to an external drive plus Magic restore;
- the Inventory UI hidden on the Master;
- a Windows 7 Office build;
- low-RAM hardening.

Nine domain designs were produced. This plan merges them into one dependency-ordered sequence of coordinated Master+Office releases. Every cross-domain collision is resolved once, below. The collisions covered are: sync lane vs push gate, migration timestamps, notification kinds, nav ids, loopback helpers, ProgressBar, PDF preview, audit tokens and report-scope helpers.

Every phase must leave `npm run lint`, `npm run typecheck` and `npm run test` at exit 0, with the integration suites actually running. Any UI change also needs a real Electron pass. Win7 floors (Node 16.17 / Chromium 108 / Electron 22) apply from Phase 0, so later code never needs a newer API in Office, shared or ui paths.

## 2. Owner decisions (binding + designer defaults)

**Binding (from owner):**
- **Win7:** a separate legacy Office build on Electron 22.3.x. The Master stays Windows 10+.
- **Inventory:** hide the UI only. Server stock keeps running.
- **Numbering:** `PO/2026-27/00001` series, Indian FY, Master-only, serial, never reused. A final order shows its lead's number. Offline saves show "Provisional". Existing leads are back-numbered by UPDATE only.
- **Highlight:** a Server Master badge plus row highlight everywhere users appear: Users, presence avatars, chat, Logs, Printroom sender and the footer.
- **Extras:**
  - notification bell;
  - scheduled auto-backup;
  - chat extras: @mentions, unread badges, search, 5-minute own edit/delete, task read receipts;
  - auto-print station.
- **Reports visibility:** two per-tier company settings, enforced in the server. Admin and Server Master always see Reports.
- **Report scope:** office/management see self only. Admin and Server Master see anyone.
- **Backup:** plain ZIP. The password vault and vault.key are never included.
- **Master UI:** light theme default, groups Work/Catalogue/Admin/System, KPI dashboard, consistent headers, company footer, loading bars, semantic tokens only.
- **Server Master:**
  - a tier above admin, labelled "Server Master" > "Normal Admin" > "Management" > "Office";
  - sign-in is loopback only, from the Master PC's own UI, and is never cached on an Office;
  - two accounts are typed at first run;
  - an existing install is asked for the master key and then the accounts;
  - at least two must remain.
- **Master key:** the owner's master key (plaintext only in `docs/MASTER_KEY.md`) stored as an scrypt hash, behind a createDeveloperGate-style lockout. It gates Server Master username/password changes and the pairing password.
- **Basic Home:** office/management land there. Chords and tiles follow the mockup.
- **Standing rules:**
  - no money, no AI, PostgreSQL only;
  - sub-screens, never modals, for records;
  - every multi-view module folds sub-pages in the sidebar;
  - Ctrl+F → `data-screen-search`;
  - ADD-only migrations pinned in `DELIBERATELY_LAST`;
  - controls a role lacks are absent;
  - full scope.

**Designer defaults the owner should know:**
- **Cross-panel ordering:** one Master push gate (`push-gate.ts`). A gate entry is one push request. The gate gathers before applying:
  - 100 ms when a push carries a live create;
  - **6 s when a push carries a `*.create` whose HLC is older than 10 s** (an offline backlog; 6 s is `reconnectionDelayMax` + 1 s, so Offices reconnecting in the same LAN blip are ordered together);
  - 5 s after Master boot.

  Order is HLC physical → counter → device code (A–Z) → mutationId (A–Z). Backlogs arriving more than ~6 s apart are numbered at arrival, because "never reused" beats timestamp order outside the window.
- **Offline-ordering limits:** offline stage changes that lose on HLC become Conflicts instead of silently overwriting. Clock skew over 2 minutes shows a banner and is not corrected.
- **Detection timing:** a silent link drop shows within ~10 s (heartbeat 4 s/6 s); a pulled cable within 2 s; reconnect within 5 s. "Nanosecond" is not physically achievable.
- **Online save:** an Office save waits up to 5 s for the number, then shows "Provisional".
- **Presence:** held in memory only (10 s beat, 30 s TTL). Avatars sit top-right in the record sub-screen's page header, with a compact stack on board cards. Someone else's save on an open record shows "X saved this at 10:42" with Reload theirs / Keep mine.
- **First-run upgrade flow: mandatory on the Master PC, no skip.** Before the Master-PC sign-in screen (loopback, `serverMasterSetupNeeded`), the master key and then the two accounts are required. LAN browsers and Offices keep working meanwhile, so nobody else is locked out.
- **Master ID:** not changeable (it would orphan every pairing). The pairing password is changeable with the master key.
- **Master key:** no `.env` override. Tests inject a hash through gate options.
- **Logs:** Logs now also appear on the Office (logs.view, System group, no chord).
- **Chat:**
  - chat is permission-switched (6 keys);
  - **out of the box, office/management roles get `chat.use` + `chat.shareRecords`** (union grant in migration #5); the other four are admin-ticked;
  - a user lacking one sees a "Request access" action that notifies role editors (`access.requested`);
  - Office posts are queued offline through the outbox and pushed only while their author is the acting user;
  - reading needs the Master;
  - messages are tombstoned, never purged;
  - a record chip stores `{kind,id}` only and is labelled per viewer ("Restricted record" when out of scope).
- **Printroom:**
  - sending is online-only;
  - the Master builds the frozen sheet;
  - the claim is held while the claiming socket stays connected (released on disconnect, stale after 10 min, cleared at Master boot), so two stations never double-print;
  - printable payloads are stripped after 30 days, while the who/when record is kept forever;
  - **`print.station` is a deliberate cross-party grant**: a station sees and prints every job whatever the party. The permission label and `08-PERMISSIONS.md` say so.
- **Rule 4 override:** print jobs ARE written to the activity log (sent/printed/unprinted/cancelled). Chat messages, presence, print status ticks and connect/disconnect are not.
- **Reports:**
  - 15 report kinds (table in Phase 5); counts, pieces, boxes, kg and days only;
  - Office Reports are online-only;
  - **existing office/management roles ARE union-granted `reports.view` + `reports.export`** (migration #4). Scope is self-only, and the two visibility switches (default on) are the off control.
- **Party file format:** fixed at 12 English columns (table in Phase 5); custom fields are not included; UTF-8 with BOM.
- **Backup restore:** keeps pairing. Offices reconnect to a replacement Master by themselves through **proof-checked** rediscovery. Restore replays migrations so backfills apply.
- **Auto-backup:** per PC, off by default, 21:00, keep 7.
- **FAT32:** an archive estimated over 4 GB on a FAT32 target is refused up front with "format the drive as exFAT/NTFS" (no split sets).
- **v1 `.obbackup` restore** keeps its `storage.manage` gate, unchanged. The new archive restore needs `storage.backupAll` + loopback + master key.
- **PO counters:** the catalog-reload CLI never resets `po:%`. Developer reset (DROP SCHEMA, back to first run) is a factory reset, the same as a new install.
- **Shortcuts:** one chord map for both panels. Alt+1..9 follow the mockup, Chatroom is Alt+C and Printroom is Alt+P, with **no darwin Meta override for letter chords**. Master Admin items lose their Alt digits. Party access moves to Catalogue on the Master.
- **Theme:** the Master switches to light. The theme key is bumped to `ob.theme.v3`, so a Master that had chosen dark resets once.
- **Low RAM:**
  - at most 4 live screens when `deviceMemory ≤ 4` **or undefined** (LAN http Chrome); screens with open records/drafts are pinned;
  - rarely used screens load lazily;
  - Kanban caps at 60 cards per column;
  - renderer heap 1024 MB and Office server floor 1024 MB on ≤4.5 GB PCs (ia32: 1024 MB ceiling);
  - PostgreSQL gets small-memory `-c` flags;
  - the knex pool stays at 10, because the push gate removes pool starvation;
  - exports stream (xlsx WorkbookWriter, pdf yields per page) so the heartbeat never stalls.

- **Encoding:** UTF-8 with BOM for CSV, so Excel reads non-ASCII names; XLSX sheet "Parties". The header row is required and in this order.
- **Limits:** 5 000 data rows and 5 MB per file.
- **Aliases** are case- and space-insensitive.

| # | Header | Required | Max | Validation | Aliases |
|---|---|---|---|---|---|
| 1 | Party Code | update mode: yes; create: blank (auto) | 20 | existing code pattern | Code, PartyCode |
| 2 | Name | yes | 120 | non-blank | Party Name, Party |
| 3 | Phone | no | 20 | phone rule | Mobile, Phone 1 |
| 4 | Alt Phone | no | 20 | phone rule | Phone 2, Alternate Phone |
| 5 | Email | no | 120 | email | E-mail |
| 6 | Address Line 1 | no | 200 | — | Address, Address 1 |
| 7 | Address Line 2 | no | 200 | — | Address 2 |
| 8 | City | no | 80 | — | Town |
| 9 | State | no | 80 | — | — |
| 10 | Pincode | no | 10 | 6 digits | PIN, Pin Code |
| 11 | GST Number | no | 15 | GSTIN pattern | GSTIN, GST |
| 12 | Notes | no | 1000 | — | Remarks |

Modes:
- **create-only**: rows with a Party Code are row errors. A row whose name+city matches a live party is skipped.
- **update-by-code**: an unknown code is a row error. Blank cells leave fields unchanged. Each updated row passes `requirePartyAccess`.

There are no money columns (no credit limit or balance). Custom fields are not included.

## 5. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Push gate serialises every push, so a reconnect burst waits in line | Throughput is unchanged because `master_clock` already serialises writes. Per-panel coalescing stops duplicate stacking. The Office `sync:push` ack is 60 s (1.2 Offices: 15 s, covered by a test) and duplicates replay. `ponytail:` notes give per-tenant lanes and batch slicing as the upgrade path. |
| Timestamp order holds only inside the gather windows | The 6 s backlog window covers same-blip reconnects. Documented as the ceiling of "strictly serial, never reused". Clock skew over 2 minutes is surfaced with a banner. |
| Retryable error mid-gate loses dependent offline edits | Gate entry = push request. A failure skips the rest of that entry unrecorded. Covered by a test. |
| Heartbeat 4 s/6 s flaps on a Master stall over 10 s | xlsx streams, pdf yields per page, and export caps hold; an event-loop-delay test covers it. Reconnect jitter is 0.5. If logs show flaps, raise `pingTimeout` first. |
| A missed `owner_id` predicate leaks figures | `DateRange.ownerId` is required (compiler-enforced) and an integration test loops over every report kind. |
| Party export/import or chat chips bypass Party Access | `partyScopeSql` on export, `requirePartyAccess` per updated row, chips resolved per viewer. Covered by tests. Printroom is a documented cross-party grant. |
| Server Master session refused on an unpatched `resolveSession*` caller | Grep every caller. The default address refuses. A supertest loopback test exercises `/me`, sockets and admin routes. |
| Server Master obtained through a panel socket from loopback | Panel sockets refuse server_master unconditionally. Covered by a test. |
| A grant migration forgets `server_master` | The integration test asserts Server Master = `allPermissions()`. |
| Fixture self-heal deletes the Server Master role | The self-heal keeps `is_system` roles (Phase 2). |
| Version skew between Master and Office | Protocol handshake with a 426 early refusal; coordinated releases; update the Master first; the Office refuses a wrong-platform manifest. 1.2 Offices are re-snapshotted after a party import. |
| Rediscovery adopts an impostor Master and leaks panel secrets/passwords | HMAC proof over the `master_proof_key` before any secret is sent. A panel without a key is never auto-rediscovered. |
| A missing panel row wipes pairing | Only an explicit revoke from the same `masterUniqueId` clears credentials. `panelNotPaired` shows "not recognised" and retries. |
| Offline chat post stalls lead sync or posts as the wrong user | The Office pushes `chat.post` only while its author is the acting user. Covered by a test. |
| Shared Office PC shows the previous user's chat/notifications | `forUserId` on every per-user push plus the Office `broadcastForUser` filter; the outbox merge is filtered by author. |
| Nav churn across chat, print, reports and logs | Rows land with their screens per phase, so the source-text guards stay green. Phase 1 provides the tuple shape. |
| Hidden kept-alive note portals double-print | Single `printOnly()` with a print-CSS rule, covered by a test. |
| Minimised station double-prints or stalls | Background throttling is off in station mode, and the claim is held by a connected socket. Covered by a test. |
| ScreenHost eviction loses unpinned state | SubNav-registry pinning plus `addLead`. Audit the Settings/Fields editors and pin any that hold drafts. |
| Chat fan-out resolves an actor per socket | One shared `emitToActors`, bounded by `userIds` prefiltering. `ponytail:` per-socket cache if a profile ever asks. |
| Plain ZIP exposes password hashes and proof keys | Owner choice. README and on-screen "keep this drive safe" wording. Panel secrets and the pairing password hash are not crackable offline. Whoever holds the ZIP already holds the business data. |
| Replay restore is not one transaction | Pre-restore safety archive (replace mode) or drop-and-remigrate (first run). The error names the safety path. Sockets are disconnected and commands refused during maintenance. |
| Oversized or malicious archive fills the disk | Entry allowlist, size caps vs the manifest and free space, yauzl validation. |
| FAT32 USB drive with an archive over 4 GB | Pre-flight refusal with exFAT/NTFS guidance before any long write. |
| `session_replication_role` needs superuser on an external DB | Surface the Postgres error (existing v1 limitation). |
| Electron 22 has no Chromium security fixes | LAN-only, sandboxed, origin-locked. Owner trade-off recorded in `docs/WINDOWS7.md`. |
| ESM `office/dist` / CJS shell under Electron 22 | The `{"type":"commonjs"}` marker in `electron/dist`. `legacy-runtime` CI launches Electron 22 and runs `office/dist` on real Node 16.17.1. Fallback: a CJS bundle for the legacy server only. |
| Unit tests cannot run on Node 16 (vitest ≥18) | Static legacy-compat tests plus the real-runtime smoke. |
| `crypto.randomUUID` is missing on LAN http origins | `getRandomValues` hex for presence tab ids and print request ids. |
| `navigator.deviceMemory` is missing on LAN http | Undefined is treated as low memory (budget 4). |
| Mac browser chords hijack Copy/Print | Letter chords have no Meta override. Covered by a keys test. |
| About 650 i18n keys to add | Added per phase. The activity lock is append-only, so token names are final before commit. |
| Restore from an old backup removes the Server Masters | `ensureServerMasterRole` plus the mandatory Master-PC flow. Admins can still sign in from LAN browsers. |
| Theme key bump resets a deliberate dark choice | Release-note line. |
