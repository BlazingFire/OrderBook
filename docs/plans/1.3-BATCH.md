# OrderBook 1.3 — realtime rules, Chatroom, Printroom, Server Master, Backup & Magic restore, Reports, Basic Home, Win7

## Context

The owner asked for one large batch on top of 1.2.5 (`5ed91cc`):
- six realtime/sync rules: instant offline/sync state, Master-assigned pending-order numbers, presence avatars, complete logs, a notice after 1 h offline, and deterministic offline ordering;
- two new modules, **Chatroom** (text only, groups, tasks, pins, announcement groups, record chips) and **Printroom** (shared print queue for Dispatch/Filling notes);
- a **Server Master** tier above Admin, gated by the master key the owner's master key (plaintext only in `docs/MASTER_KEY.md`), with two accounts (main and backup);
- **Backup all to external drive** as a plain zip with photos, **Magic restore** at first run, and scheduled auto-backup;
- **Basic Home** (mockup `Basic Home · Office Panel`) as the landing screen for Office/Management, a Master UI refresh, and loading bars;
- reports (user-, party- and product-wise, Excel/PDF, both panels, per-tier visibility and scoping), and party CSV/XLSX import/export;
- the Master's Inventory UI hidden, notes from pending orders, the device code on the Office start page, Master PDF preview;
- low-RAM hardening for 3–4 GB PCs and a **Windows 7** Office build.

The rule is **don't break anything**.

How this plan was made:
- 10 read-only mappers covered the code, with a critic pass.
- 9 domain designers produced designs, which an integrator merged.
- 3 adversarial reviewers raised 47 issues (2 blockers, 27 major, 18 minor); each was fixed or rejected with evidence.

The full per-domain designs are in the session's workflow journal (`~/.claude/projects/C--Users-Z-Desktop-OrderBook/<session>/subagents/workflows/wf_fffedb77-d52/journal.jsonl`). **Step 0 of implementation copies this plan plus those designs into `docs/plans/1.3-BATCH.md`** so the detail outlives the session.

**Designer defaults (confirm or change at approval):**
- **Printroom is a deliberate cross-party grant.** A `print.station` holder sees and prints every job whatever the party, which matches "one PC prints for everyone".
- **FAT32 targets.** A backup estimated over 4 GB onto a FAT32 drive is refused up front with "format as exFAT/NTFS". No split archives.
- **Default grants.** Office/Management roles get `reports.view` + `reports.export` and `chat.use` + `chat.shareRecords` out of the box. The other chat capabilities are admin-ticked; a user without one sees **Request access**, which notifies role editors.
- **Detection times.** A silent link drop shows within about 10 s (heartbeat 4 s / 6 s). A pulled cable shows within 2 s. Reconnect takes up to 5 s. "Nanoseconds" is not physically possible.
- **Online save.** An Office save waits up to 5 s for its PO number, then shows Provisional.
- **Rule 6 order.** HLC physical ms, then HLC counter, then device code A–Z, then mutation id A–Z. The Master push gate collects pushes for 100 ms (live), 6 s (offline backlog) and 5 s (after boot). Offline stage changes that lose become Conflicts. Clock skew over 2 minutes shows a banner.
- **Presence.** Held in memory only (10 s beat, 30 s TTL). Avatars sit top-right in the record header, with an accent ring meaning "editing". Someone else's save offers "Reload theirs / Keep mine".
- **Chat delivery.** Office posts queue offline through the outbox and send only while their author is the acting user. Reading needs the Master. Deleted messages become tombstones; nothing is purged.
- **Printroom sending** needs the Master to be online. Payloads are stripped after 30 days; the who-printed-when record stays.
- **Rule 4 audit.** Print jobs (sent, printed, unprinted, cancelled) and chat governance actions are audited. Chat messages, presence and status ticks are not.
- **Logs** now also appear on the Office (`logs.view`).
- **Shortcuts:**
  - Alt+1..9 as in the mockup: Basic Home, Dashboard, Pending, Final, Conflicts, Products, Parties, Party access, Settings.
  - **Alt+C** opens Chatroom and **Alt+P** opens Printroom.
  - The Master's Admin items lose their Alt digits.
  - The Master theme key changes to `ob.theme.v3`, so the theme resets to light once.
- **Low RAM:**
  - ScreenHost keeps at most 4 live screens on PCs with 4 GB or less (or when the browser does not report memory); screens with open drafts are pinned.
  - Lazy screens.
  - Kanban caps at 60 cards per column.
  - Renderer heap is 1024 MB on PCs with 4.5 GB or less.
  - The Office server heap floor is 1024 MB.
  - PostgreSQL gets small-memory flags.
  - Exports stream.

## How it will be executed

- Work goes on `main`: owner policy, recorded in memory. `git diff --ignore-all-space` is how to see real changes, because of CRLF.
- **Per phase, one ultracode workflow:**
  1. Implementers run in sequence, one per slice: shared + Master server → Office server → ui + web → electron/tools. They run in the main tree, not parallel worktrees, because `en.ts`, `hi.ts`, `socket.ts` and both `App.tsx` files are touched by every slice.
  2. A verifier runs `npm run lint`, `npm run typecheck` and `npm run test`, each separately, each exiting 0, and **confirms the `*.integration.test.ts` suites actually ran rather than skipped**. From Phase 0 on it also runs `npm run smoke:legacy`.
  3. Three adversarial reviewers check regressions/guards, requirement coverage, and security/performance/Win7 floors.
  4. A fix loop runs until reviewers come back dry.
  5. A real browser and Electron pass of both panels runs through the preview tools: 1024×768 and 4K, 79% and 157%, light and dark.
- **Per phase, before commit:**
  - `docs/STRUCTURE.md`;
  - `HANDOFF.md` with a dated entry;
  - the `docs/AI_COLLABORATION.md` change log;
  - `docs/backend-modules/04-API-CONTRACT.md` when the wire changes;
  - `git status` checked for untracked `??` migrations.
- **Builds:** bump the version before any `npm run release`, with 1.3.0 for the batch and a patch bump per extra build. Never rebuild under the same version. Update the Master before the Offices.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| The push gate serialises pushes | `master_clock` already serialises writes. Per-panel coalescing; a 60 s ack (1.2 Office: 15 s, tested); `ponytail:` per-tenant lanes as the upgrade path. |
| Timestamp order holds only within the gather windows | The 6 s backlog window covers reconnects after one blip. Documented as the limit of "never reused". A clock-skew banner shows over 2 minutes. |
| A 4 s / 6 s heartbeat flaps when the Master stalls | Streaming xlsx, PDF yields per page, export caps, and an event-loop-delay test. Raise `pingTimeout` first if flaps appear. |
| A missed owner predicate leaks figures | `DateRange.ownerId` is required, and a test loops over all kinds. |
| Party scope bypass via export, import, chips or presence | `partyScopeSql`, per-row `requirePartyAccess`, per-viewer chips, `mayReceive`. Printroom is the documented exception. |
| A Server Master is reached via a panel socket or LAN | Panel sockets refuse it unconditionally; `resolveSession` checks loopback; tests cover both. |
| Fixture self-heal or grant migrations drop Server Master | The self-heal keeps `is_system`; `server-master.integration` asserts `allPermissions()`. |
| Master/Office version skew | Protocol handshake answers 426; coordinated releases with the Master first; wrong-platform manifests refused; 1.2 Offices are re-snapshotted. |
| An impostor Master hijacks rediscovery | The HMAC proof runs before any secret is sent; a panel without a proof key never auto-rediscovers. |
| A missing panel row wipes pairing | Only an explicit revoke from the same `masterUniqueId` clears credentials. |
| A chat post stalls sync or posts as the wrong user | Held per author, filtered per user, tested. |
| Nav churn breaks the source-text guards | Rows land with their screens, phase by phase. |
| Double printing from kept-alive portals or two stations | `printOnly()` plus a socket-held claim, tested. |
| ScreenHost eviction loses a draft | Sub-nav pinning and `addLead`; audit the Settings/Fields editors and pin any that hold drafts. |
| The plain zip exposes password hashes | The owner's choice; README and on-screen "keep this drive safe"; the vault and vault.key are excluded. |
| A restore is not one transaction | A safety archive first; maintenance mode; the error names the safety path. |
| A malicious or oversized archive | Allowlist, caps, free-space check, yauzl validation. |
| Electron 22 has no Chromium security fixes | LAN-only, sandboxed, origin-locked; the trade-off is recorded in `docs/WINDOWS7.md`. |
| Vitest cannot run on Node 16 | Static legacy-compat tests plus a real Node 16 / Electron 22 smoke in CI. |
| About 650 keys of real Hindi | Translated per phase; coverage tests block stubs; the activity lock is final before commit. |
| The theme key bump resets a chosen dark theme | A release-note line. |
