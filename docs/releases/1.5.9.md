# OrderBook 1.5.9

> ## ⚠ Read before installing: this update clears the catalogue and every order
>
> 1.5.9 changes how sub products are stored (the variant layer is gone: a sub product carries its own code,
> colours and print side). For this one update the company starts the catalogue and the order book again.
>
> **Deleted** — once an administrator confirms it on the Master, never by the install itself:
> every new order and final order (with their lines, notes and print jobs), every sub product, every product
> (main product) and every product photo.
>
> **Kept:** parties, users and roles, settings, option lists (packaging, colours, grades, brands), the
> activity log, chat, and order numbering — the next order number carries on from the last one, so a number
> already printed on paper is never used again.
>
> **How it happens:**
>
> 1. The update installs as usual (the nightly update or by hand). **Nothing is deleted at install**; the
>    Master starts on the existing data, moved to the new shape.
> 2. When an administrator next signs in to the Master, a written warning opens listing exactly what is deleted
>    and kept, with numbers. It asks for a tick ("I understand") and the administrator's own password. "Later"
>    closes it; it opens again next time.
> 3. On confirmation the Master first saves a **full backup** (data and photos) in its data folder, in
>    `pre-1.5.9-reset\`. If the backup fails, nothing is deleted. Then it deletes, and every Office panel
>    receives the empty catalogue.
> 4. Orders still waiting on an Office panel to be sent (made offline) are dropped too, once that panel has
>    updated; the panel says how many, once.
>
> This applies to 1.5.9 only. Later updates keep all data, as before.

## Install order

1. Install the Master Setup over the existing install first. Do not uninstall; the data is kept until the
   confirmation above.
2. Then update each Office (its Updates screen, or the Office Setup / Win7 Office Setup).
   **A 1.5.8 Office cannot sync with a 1.5.9 Master** — it would misread the new catalogue — so the Master turns
   it away until it updates. Meanwhile it keeps working offline on what it already had, and it can still
   download its update from the Master.
3. Enter or import the new catalogue after the reset.

## What changed

- **Sub products without variants.** Product → sub product, each with its own code, weight, colour options,
  print side (Left / Right / Default) and default packaging. The old variants table is kept, unused.
- **Panel protocol 13**, and a minimum of 13: the Master refuses older Offices (`panelUpdateRequired`). Support
  can let an older Office in temporarily with `ORDERBOOK_MIN_PANEL_PROTOCOL` on the Master.
- **Migrations (all add only):** `20261116000000_sub_product_code_colours_print_side` (columns on `products`
  filled from the variants every product already had), `20261118000000_note_dealer_and_grade_size`, and
  `20261119000000_release_reset_1_5_9`, which only records that the reset is waiting for confirmation.
- Products: the Photo import menu is removed; photos are editable while a sub product is being edited; the
  Default packaging choice is a menu that follows the packaging list in Fields.
- Notes: dealer code and grade text size per order, the creator's name on the sheet, size text off every
  printed document.
- Sidebar: Conflicts moved under Admin (Alt+5 unchanged). Basic Home: a per-user tile size.
