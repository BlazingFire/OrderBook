# OrderBook 1.5.8

This release makes the data safer against power cuts, full disks and interrupted
restores, and carries the fixes found while testing 1.5.7. It adds no migration, and
the panel protocol stays at 12. An install already running keeps its database, its
login and its folder permissions exactly as they are.

## Install order

As before:

1. Install the Master Setup over the existing install first. There is no need to uninstall it; the data is kept.
2. Then install each Office Setup, or the Win7 Office Setup on Windows 7. The Master carries the Office setup of
   its own version, so its Offices can update with no internet.
3. From then on, updates are automatic on the Master. Each Office updates from its own Updates screen.

## What changed

### Data safety

- **A power cut during a restore no longer leaves an empty Master.** `restore-pending.json` is written before the
  old data is dropped. If it is still there at the next boot, the data from before the restore is put back from
  the safety copy, and the Server Masters are told in the bell.
- **Backups are flushed to the disk before they count as finished,** so a safety copy or a USB drive pulled out
  straight after is complete.
- **The Office's queued changes, pairing, sign-in list and id counter now survive a power cut:** temp, fsync, rename.
  Several of these used to be written straight over themselves. The Master's vault key, database password and small
  settings files get the same treatment. The Office's snapshot does not, because it is large, rewritten often and
  comes back from the Master.
- **The bell warns the Server Masters** when there has been no backup for 7 days (once a week), and when the data
  drive has under 2 GB free (once a day). They only warn: nothing is started or changed.
- **A new install's secret files are private** to its Windows account, SYSTEM and Administrators. Existing installs
  are not touched.
- **When PostgreSQL will not start,** the boot screen shows the end of `postgres.log`.

Not in this release, because each would change how a running install works: encrypted backups (a forgotten
passphrase would make a backup useless) and a database login with fewer rights (restore needs the superuser).
The Automatic backup screen now says the backups are not encrypted.

### Fixes

- A new install loads the printed catalogue and its photos again. 1.5.7 lost this when the product backup zip went.
- Several blank-colour variants on one product keep their own identity when a form re-sends them without ids. The
  save and the check on retiring a quoted variant now match rows the same way.
- A silent update can no longer stop forever on a hidden "Failed to uninstall" dialog with the server already
  stopped. It exits, and restarts the installed program.
- Several variant rows count as a product with variants when the caller does not say.
- Dead Integrations code, the `api.manage` permission and the unused "Allow other software to connect" setting are
  gone. Old activity log entries and old backups still read correctly.
- Start fresh is the last option on the Delete data screen.
