# OrderBook 1.4.3

Released 2026-10-05. Signed with the release key `release-2026-10-01`. Setup installers only.
Download: <https://github.com/BlazingFire/OrderBook-Releases/releases/tag/v1.4.3>

## Install order

As before:
1. Install the Master Setup over the existing install first. There is no need to uninstall
   it; the data is kept.
2. Then install each Office Setup, or the Win7 Office Setup on Windows 7.
3. From then on, updates are automatic.

## What changed

- **A smoother, faster app.**
  - Lists and records you have just looked at open straight away instead of being asked for
    again. They are refreshed in the background and dropped the moment anything changes, so
    you never see an old figure after a change.
  - The Chatroom opens a conversation you have seen before at once, and new messages appear
    without the list being reloaded.
  - A burst of changes (a catalogue import, for example) refreshes the screen once, not once
    per record.
  - Chatroom, Printroom, Reports, the gallery and the Lists screens load the first time you
    open them, so the app starts a little sooner.
  - The Master now tells the browser it may keep the program files, so reopening the app is
    quicker (product pictures were already kept).
- **Protection against floods.** The Master limits how fast one PC can sign in, change
  passwords, create reports and PDFs, upload files or call the public API. The limits are far
  above normal shop use. A PC that goes over one is told how many seconds to wait, and the
  Master carries on for everyone else.
- **The app should not crash.**
  - A screen that fails shows a short "try again" panel in its own place instead of taking the
    whole window with it.
  - A request that fails without anyone catching it now shows a message instead of leaving a
    screen that looks stuck.
  - The Master and the Office carry on after a stray error. If it keeps happening, the program
    stops cleanly and restarts itself.
  - A request that cannot be read, is too large, or contains an impossible value is refused
    with a plain message (400 or 413), not a server error.
- **Sign-in window.**
  - A tidier layout with a clear heading, a banner explaining why you are signed out, a Caps
    Lock reminder under the password box, and the password box emptied and ready again after a
    wrong password.
  - It warns when this PC has less than 7.5 GB of memory or only 2 processor cores, and shows
    the figures, because such a PC will feel slow.
- **Save to a text file.** The screens that show a password or other detail only once (first
  setup, the first sign-in details, a new password for a person, a recovered account password, an API
  token, a replaced pairing password, a restore, and the Office's setup summary) now have a
  **Save to .txt** button. The file says what it is, when it was saved and on which PC, and is
  kept on that PC only. Nothing is sent anywhere. Keep it private.
- **Assigning roles.** Choosing a person's role now shows each role as a card with its
  permission counts, what it can change and what it can only view. Changing a role asks you to
  confirm and says how many permissions are gained or lost. The role editor can search
  permissions, select a whole group, and shows when there are unsaved changes.
- **Pending and Final orders in pages.** Both lists show one page at a time, with a page size of
  25, 50, 100, 200 or 500 (remembered on that PC), "Showing 51-100 of 120", and First, Previous,
  Next and Last. The stage chips show the true number of records in each stage, on every page.
  The Office pages its local copy the same way.
- **Find and delete duplicate products.** A new **Duplicates** page under Products lists
  products (and sub products) that repeat, shows which copy to keep, and deletes the others
  into the Recycle Bin. A copy that a live pending or final order uses is refused, and a
  product that still has sub products must have them removed first. Deleting on the Master
  removes the copy from every Office.
- **Renames reach every Office.** When a party or a person is renamed on the Master, the new
  name now appears on the Offices' existing pending and final orders straight away, instead of
  after each order next changes.

## Compatibility

- An Office still on 1.4.2 keeps working with a 1.4.3 Master until it updates. The new
  screens' data is additive: the Office keeps paging its own copy of the lists.
- Nothing is lost or converted by the update. No database change removes or rewrites data.
- Duplicate deletion uses the existing Recycle Bin, so a deleted copy can be restored.
