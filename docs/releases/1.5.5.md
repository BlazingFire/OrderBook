# OrderBook 1.5.5

Not yet released: the next published build after `v1.5.2`. Versions 1.5.3 and
1.5.4 were committed to `main` and built on this PC as unsigned setups, but
never published to the releases repository — so 1.5.5 carries all three
bundles at once, signed with the release key `release-2026-10-01` when the
release workflow publishes it.

## Install order

As before:
1. Install the Master Setup over the existing install first. There is no need to uninstall it; the data is kept.
2. Then install each Office Setup, or the Win7 Office Setup on Windows 7. The Master carries the Office setup of
   its own version, so its Offices can update with no internet.
3. From then on, updates are automatic.

One additive database change since 1.5.2: each record remembers its Dispatch
note column ticks (nullable columns, nothing rewritten). The panel protocol
moves 11 to 12 for the new final-order PDF command (`order:pdf`); it is
additive, but an Office still on 1.5.4 is held on the "Update needed" screen
until it installs 1.5.5 — update the Master first, then the Offices, as above.

## What changed

### Order notes bundle (from 1.5.3)

The Dispatch note screen's Packing / Grade / Colour tick boxes are saved on
the record with a Save button, and every rendering — preview, print, PDF
and the print room — prints exactly the saved choice. Filling and Dispatch
notes and their PDFs show the order totals (TOTAL) on every page. The Master
lead screen and the Office lead board show Filling note, Dispatch note and
Preview PDF directly. Notes print bold by default (a company switch, on
unless changed). Editing a product patches pending leads and undispatched
orders while dispatched history stays frozen, with a before/after conflicts
screen. Product imports are reviewed row by row (create, update or skip;
unchanged rows default to skip), and the old Duplicates page now lives as a
tab on the conflicts screen.

### Printroom PDF work (new in 1.5.5)

The printroom path is now end to end: a shared printroom domain, a fixed
note renderer on the Master, a lead PDF in the desktop shell, and OrderNote
screens on both panels with a Send-to-printroom dialog. The order record
gains its third button — the fixed-layout final-order PDF (the mirror of
lead PDF), served by the new `order:pdf` command (`orders.export`,
desktop app only, online-only).

### Also in this build

- Numeric variant codes print on the coded half of notes (Gate 0 fix).
- Rust sidecar groundwork: native core, helper and bridges with four wired
  paths plus parity tests. Internal only — no behaviour change.
- Duplicate-list styles moved to the shared kit; five dead interface keys
  removed.
